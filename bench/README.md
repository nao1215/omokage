# Benchmarks

omokage is measured the way a user runs it, one process per call from start to exit, with [himorime](https://github.com/nao1215/himorime). himorime builds omokage, runs each command in interleaved rounds, and reports latency, CPU time, peak RSS and, for the long draft, throughput.

```console
$ go install github.com/nao1215/himorime@latest
$ make bench            # himorime run bench
$ make bench-compare    # himorime compare --against main bench
```

## Regression suite: himorime.yaml

`make bench-compare` checks main out into a temporary Git worktree, builds it and your working tree, and measures both in the same rounds, so a background job slows both revisions instead of one. `BASE=v0.2.0 make bench-compare` compares against another revision, and `himorime run --filter '^check' bench` measures the check benchmarks only.

On a pull request, `.github/workflows/bench.yml` runs `himorime ci bench` the same way, with the base of the pull request as the base, on one runner. The job fails when a command is slower, uses more CPU time or more memory than the base beyond the tolerance in `himorime.yaml` with 95% confidence. A difference too close to call is reported as inconclusive and does not fail the job. The comparison is on the job summary page and the JSON report is kept as an artifact.

The posts are generated by `gen.sh` before measuring, from the mixed Japanese and English paragraph the Go benchmarks used, so no fixture is committed; both revisions run the working tree's `gen.sh`. Every benchmark keeps its store in its own directory through `OMOKAGE_HOME`.

| Benchmark | Commands | Measures |
|-----------|----------|----------|
| `version` | `omokage version` | starting omokage |
| `train 5 posts` | `train --author me posts` | extracting the features of 5 posts of 8 paragraphs and aggregating them; the Japanese analyzer loads its dictionary once per process |
| `train 50 posts` | `train --author me posts` | the same over 50 posts, where extraction and aggregation dominate |
| `check 8 paragraphs` | `check` with the default output, `--explain`, `--format json` and `--score-only` | scoring a draft against a profile of 50 posts, and the detailed paths that localize the drifting paragraphs |
| `check 400 paragraphs` | `check`, `check --explain` | scoring a long draft, where extracting its features dominates |
| `diff 8 paragraphs`, `diff 400 paragraphs` | `diff a.md b.md` | comparing two posts without a profile |
| `check error` | `check` of a missing file | the error path, exit 1 |

These replace the Go benchmarks that were in `internal/feature` and `internal/profile`: `ExtractText` and `Aggregate` are `train`, `Score` is `check`, `Explain` is `check --explain` and `--format json`, and `Compare` is `diff`.

Numbers from different machines are not comparable; compare revisions on one machine, as `make bench-compare` and CI do.
